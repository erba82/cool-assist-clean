# گزارش بازسازی حاکمیتی و اعتبارسنجی مهندسی Cool‑Assist

**تاریخ:** ۲۲ اوت ۲۰۲۶
**دامنه:** موتور محاسبات، انتخاب تجهیزات، P&ID، BIM، BOM، دفترچه محاسبات و چاپ
**وضعیت انتشار:** **Preliminary / review-gated**؛ این گزارش مجوز خرید، IFC، ساخت، HAZOP یا تأیید انطباق با استاندارد نیست.

## ۱. جمع‌بندی مدیریتی

نقد کاربر دربارهٔ خروجی قبلی کاملاً وارد بود. خروجی‌هایی مانند ترکیب نامعتبر «GEA + Mycom»، ظرفیت و موتور فرضی، یک کمپرسور برای بار بزرگ، حجم/فشار مخزن و DN بدون ورودی هیدرولیکی، و چیدمان ارتفاعی صرفاً نمایشی، دادهٔ مهندسی قابل استناد نبودند. مسیرهای تولید این مقادیر از موتور حذف یا به‌صورت صریح **review-gated** شدند. اکنون نرم‌افزار می‌تواند اطلاعات پروژه را استخراج کند، یک **Design Basis** ساخت‌یافته با منشأ هر فرض بسازد، اجازهٔ تغییر/تأیید بدهد و تنها سپس محاسبهٔ مقدماتی component-based را اجرا کند.

اصلاح کلیدی، «صادق‌کردن» خروجی است؛ نه جایگزین‌کردن دادهٔ ساختگی با ظاهری حرفه‌ای‌تر. بنابراین تا زمانی که نقشهٔ عملکرد سازنده، envelope، موتور، اطلاعات مخزن، مسیر لوله، NPSHr و داده‌های elevation دریافت نشده‌اند، تجهیز به‌عنوان مدل/تعداد/ظرفیت قابل خرید اعلام نمی‌شود. P&ID و BIM در چنین وضعیتی topology و contract ورودی را نشان می‌دهند، نه طراحی نهایی.

| حوزه | وضعیت پیش از بازسازی | وضعیت فعلی |
|---|---|---|
| بار برودتی | وابستگی عملی به kW واردشده یا پیش‌فرض پنهان | Design Basis پیشنهادی، قابل تغییر و قابل تأیید؛ تفکیک facts از assumptions |
| کمپرسور | برند/مدل/ظرفیت/موتور و تعداد قابل جعل | cycle مقدماتی جدا از انتخاب سازنده؛ map، envelope و motor gate الزامی |
| اواپراتور و کندانسور | مدل، فن، DN و قیمت حدسی | duty brief و `manufacturer-map-required` |
| مخزن و پمپ | حجم، pressure، head، power و nozzle rule-of-thumb | dossier بدون حجم/فشار/نازل/پمپ قطعی تا دریافت calculation و evidence |
| P&ID | DN review و topology روغن/TS ناکامل | line ID، وضعیت hydraulic sizing، حلقهٔ TS–oil cooler و elevation contract |
| BIM | جابه‌جایی خودکار برای «ظاهرِ درست» | فقط elevation اعلام‌شده؛ screening بدون حرکت هندسه و بدون ادعای NPSHa |
| BOM / قیمت | ظاهر انتخاب و قیمت/تعداد قابل برداشت به‌عنوان خرید | quotation/evidence-gated؛ tier فعال فقط preview است، نه تجهیز انتخاب‌شده |
| دفترچه و چاپ | چاپ shell وب‌اپ | report print-media مستقل با A4 landscape، title و حذف کنترل‌های UI |

## ۲. قرارداد عملیاتی جدید: Design Basis

روند طراحی از این پس باید این ترتیب را طی کند:

> **Parsed facts → Proposed assumptions → User amendment / approval → Preliminary component calculation → Manufacturer/map gate → Hydraulic/layout/NPSH gate → Engineering review**

اطلاعاتی مانند شهر، محصول، تعداد اتاق، ابعاد و دمای نگهداری از متن کاربر جداگانه ثبت می‌شوند. مواردی مانند dry-bulb/wet-bulb، دمای زمین، ضخامت عایق، profile درب، gains داخلی، throughput محصول، setpointهای cycle، redundancy و NPSH/elevation در assumption register ظاهر می‌شوند و قابل اصلاح هستند. تأیید کاربر فقط اجرای محاسبهٔ مقدماتی را مجاز می‌کند و هیچ‌گاه به‌معنای تأیید خرید یا IFC نیست.

| گیت | شرط رفع گیت | خروجی ممنوع تا رفع گیت |
|---|---|---|
| `manufacturer-performance-map-required` | مدل، revision، map در نقطهٔ کار، envelope، motor و evidence سازنده | ظرفیت واحد، توان موتور، تعداد duty/standby، مدل نهایی |
| `hydraulic-input-required` | state خواص با منبع، mass flow، route، roughness، fittings و criterion افت فشار | DN و افت فشار نهایی |
| `declared-elevation-and-NPSH-required` | datum، nozzle/centreline elevations، NPSHr، طول/DN/loss مکش و state مایع | ادعای head، NPSHa یا set-out BIM |
| `supplier-quotation-required` | quote دارای URL/زمان، commercial terms و technical approval | قیمت landed، availability نهایی و procurement authorization |

## ۳. اصلاح انتخاب تجهیز و BOM

`CompressorSelector` اکنون چرخهٔ مقدماتی CoolProp را از انتخاب manufacturer map جدا می‌کند. حتی وقتی cycle قابل محاسبه باشد، `capacityPerUnit`، `motorPower`، train count، قیمت و مدل نهایی null می‌مانند مگر evidence معتبر فراهم شود. کاتالوگ موجود فقط identity candidate سازگار را نمایش می‌دهد و مدل سازنده بدون performance-map به انتخاب تبدیل نمی‌شود.

`EvaporatorSelector` و `CondenserSelector` به‌ترتیب room/process duty brief و heat-rejection duty brief تولید می‌کنند و fan، motor، DN، model یا price حدسی تولید نمی‌کنند. `VesselSelector` نیز بازنویسی شد تا rule-of-thumbهای قبلی برای حجم مخزن، design pressure، test pressure، تعداد پمپ، head، power و nozzle size را از مسیر production حذف کند. برای separator، receiver و thermosiphon فقط dossier، دادهٔ موردنیاز و status نشان داده می‌شود.

| dossier تجهیز | دادهٔ لازم پیش از انتخاب |
|---|---|
| کمپرسور | map ظرفیت در Te/Tc واقعی، envelope، موتور، کنترل، redundancy و revision |
| کندانسور | map heat rejection در شرایط هوای/آب واقعی، fan/motor، approach و control |
| اواپراتور | map duty/TD، airflow، defrost، fan/motor و room process |
| separator / receiver | inventory، liquid level، relief/design basis، code، nozzle schedule و fabrication evidence |
| pump | curve، NPSHr، state مایع، suction losses، nozzle و elevations |
| thermosiphon | oil-cooler duty/loss، source liquid level، return path و loop-loss calculation |

## ۴. P&ID و BIM آمونیاک

P&ID اکنون هر خط را با `L-###` و وضعیت DN نمایش می‌دهد. اگر محاسبهٔ هیدرولیک قابل‌ردیابی وجود نداشته باشد، مقدار DN خالی و وضعیت `hydraulic-sizing-required` است. اتصالات برای R717 سیاست joint `welded` را نگه می‌دارند و مدل یا rating ساختگی روی node کمپرسور/کندانسور درج نمی‌شود.

در topology دارای thermosiphon، منطق پیشینِ اتصال مستقیم oil separator به thermosiphon و برگشت آن فقط به نخستین کمپرسور حذف شد. ساختار جدید شامل receiver-to-thermosiphon supply، thermosiphon downcomer به oil cooler هر branch و two-phase return از oil cooler به thermosiphon است. این نمایش به‌تنهایی صحت هیدرولیکی را ثابت نمی‌کند؛ head لازم از افت فشار loop و اطلاعات واقعی oil cooler تعیین می‌شود.

BIM دیگر برای نزدیک‌شدن ظاهری به تصاویر مرجع، ارتفاع مخزن، pump یا thermosiphon را تغییر نمی‌دهد. اگر layout موجود نباشد، `layout-input-required` ثبت می‌شود. اگر elevation اعلام شود، validator فقط رابطه‌ها را screen می‌کند: separator نسبت به suction compressor، pump نسبت به separator، و source thermosiphon نسبت به oil cooler. برای pump، بدون NPSHr و suction-line loss، پیام صریح input-required باقی می‌ماند. راهنمای Frick تأکید می‌کند که source liquid thermosiphon باید بالاتر از oil cooler باشد و head واقعی تابع loss loop است، نه یک فاصلهٔ ثابت نمایشی [1]. راهنمای Sabroe نیز نقش separator/pump vessel را تشریح می‌کند اما NPSH set-out پروژه را جایگزین نمی‌کند [2].

## ۵. دفترچه محاسبات و چاپ

`CalculationBook.tsx` به گزارش چاپی مستقل تبدیل شد. media rule شامل `@page A4 landscape` است؛ کل app shell در print hidden می‌شود، تنها calculation-book root visible می‌ماند، کنترل‌های procurement/print نمایش داده نمی‌شوند و عنوان print-only به گزارش افزوده می‌شود. گزارش شامل Design Basis، assumption register، room load breakdown، provenance cycle، dossier انتخاب تجهیز، line register و status procurement است.

در E2E، کلیک واقعی روی **Print / Save PDF** با `window.print` کنترل‌شده و `media: print` اعتبارسنجی شد. شرط موفقیت شامل فعال‌شدن `print-calculation-book`، visible بودن report root، hidden شدن `.no-print` و visible بودن عنوان رسمی گزارش بود. این آزمون صحت media contract را ثابت می‌کند؛ print/PDF نهایی باید همچنان در مرورگر و پرینتر/driver مقصد کاربر بازبینی شود.

| Playwright E2E Paris | PASS | Design Basis، NVIDIA provenance، confirmation، Calculation Book، map/input gate و print-media |

سناریوی واقعی E2E عبارت بود از «5000 ton cold storage، 12 room، beef، -18°C، Paris» و ابعاد صریح هر اتاق `60 × 40 × 9 m`. پس از تأیید assumptions، برنامه **589.92 kW** را به‌عنوان حاصل اولیهٔ component-load محاسبه کرد. این مقدار **بار نهایی، ظرفیت کمپرسور یا سایز تجهیزات نیست**: throughput محصول در سناریوی frozen-storage صفر ثبت شده، profile عملیات درب و internal gains پیشنهادی بوده‌اند، cycle provider پاسخ قابل اتکای انتخاب سازنده نداده است و همهٔ selections review-gated باقی مانده‌اند.

## ۸. محدودیت‌های باقی‌مانده و اقدام بعدی

این بازسازی، خطر خروجی مهندسی ساختگی را رفع کرده است؛ اما هنوز برنامه را به software انتخاب تجهیز certified یا deliverable IFC تبدیل نمی‌کند. اولویت بعدی باید ورود کنترل‌شدهٔ mapها و datasheetهای واقعی سازنده، schema ورودی layout/NPSH در UI، محاسبهٔ هیدرولیک دارای property state/source، و evidence/fabrication contract مخازن باشد. سپس، هر model-specific selection باید توسط engineer دارای صلاحیت تأیید و version/revision آن در digital thread ثبت شود.

| اولویت | اقدام عملی | معیار پذیرش |
|---|---|---|
| ۱ | import mapهای compressor/condenser/evaporator و motor/envelope evidence | انتخاب فقط در operating point معتبر، با revision و source URL/file |
| ۲ | فرم layout/NPSH | datum، nozzle levels، NPSHr، route/loss و نتیجهٔ screening قابل trace |
| ۳ | hydraulic line input | state/source، mass flow، route/fittings/roughness/criterion و DN traceable |
| ۴ | vessel calculation package | inventory، relief/design basis، code/nozzle/material و approved fabrication dossier |
| ۵ | P&ID/BIM review workspace | acceptance checklist، diff، MOC و sign-off انسان برای هر revision |
