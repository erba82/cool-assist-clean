# ممیزی ریشه‌ای محاسبات، انتخاب تجهیزات و نقشه‌های R717

**وضعیت:** یافته‌های اولیهٔ قابل بازتولید؛ هیچ‌کدام از خروجی‌های فعلی برای خرید، ساخت یا تأیید compliance معتبر نیستند.

## شواهد رابط کاربری و خروجی فعلی

تصاویر خروجی نشان می‌دهند که یک پروژه با بار اعلامی ۱۸۰۰ kW، تنها یک ردیف کمپرسور با نشان `GEA` و مدل `Mycom OS250`، ظرفیت ۱۱۵۰ kW، آرایش `2+1` و توان ۶۰۰ kW نمایش می‌دهد. این presentation از نظر مهندسی و provenance نادرست است: برند و مدل در یک evidence record واحد نیستند؛ نقطهٔ کار و performance map برای ظرفیت ۱۱۵۰ kW نشان داده نشده‌اند؛ و motor rating/absorbed power/range در شرایط تبخیر و تقطیر معلوم نیست.

تصاویر P&ID فعلی نیز تعداد زیادی تجهیز و خط `DN REVIEW` را بدون یک cycle sheet، P&ID index، line list و مسیر process قابل بازخوانی در یک صفحه نشان می‌دهند. خروجی BIM درخت لوله‌کشی را از همان graph تولید می‌کند، اما به‌دلیل نبود قرارداد elevation فیزیکی، معادل یک مدل ساختنی یا جانمایی استاندارد نیست. پنجرهٔ چاپ نیز کل صفحهٔ وب را در کاغذ portrait چاپ می‌کند، نه یک calculation book مستقل با template چاپ.

## شواهد منبع مرجع ارسالی

نقشهٔ `ROYAFLOWDIAGRAMFINAL_001120-02.pdf` به‌صورت قطعی برچسب‌های زیر را نشان می‌دهد: **Screw Compressor No.1 تا No.6**، **-10°C / -30°C / -40°C liquid and return levels**، **-40°C separator**، **NH3 pump**، **ammonia receiver**، **thermosyphone** و دو **evaporative condenser** با مدل `TXC-180-3 DE`. همچنین به چندین شیر Danfoss از خانواده‌های SVA/FIA/ICS و قطرهای اینچی اشاره می‌کند. متن و ارتباط‌های بسیار ریز نقشه برای تبدیل خودکار به sizing یا مدل دقیق تجهیزات کافی نیستند و باید به‌عنوان evidence تصویریِ topology، نه performance data، باقی بمانند.

> تصاویر مرجع 3D ارسالی، آرایش compact کارخانه‌ای با قطارهای چندکمپرسوری، مخازن افقی، پمپ‌های روی skid زیر یا نزدیک surge/separator، مسیرهای عمودی کنترل‌شده، سکو/handrail و کندانسورهای بام را نشان می‌دهند. این تصاویر **مرجع visual/layout** هستند و منبع عملکرد، NPSH، nozzle coordinate یا ظرفیت سازنده محسوب نمی‌شوند.

## نقص‌های قطعی کد فعلی

| دامنه | شواهد کد | نتیجهٔ نادرست |
|---|---|---|
| انتخاب کمپرسور | `CompressorSelector.js` دارای bandهای ساختگی `OS/HS/REC` و مدل‌های `OS250/HSK95` است؛ `_selectManufacturer` برند را جدا و مستقل از مدل برمی‌گرداند. | ترکیب‌هایی مانند `GEA + Mycom OS250` ایجاد می‌شود و selection به performance envelope سازنده متصل نیست. |
| تعداد و redundancy | `_determineCount` فقط `ceil(load/capacity)` و یک standby ثابت اعمال می‌کند؛ `safeLoad` نیز برای بار نامعتبر به ۱۰ kW تبدیل می‌شود. | نه N+1 واقعی در operating point ثابت می‌شود، نه partial-load/lead-lag، motor loading یا unloading بررسی می‌شود. |
| خواص و cycle | selector فشار و COP fallbackهای ساده دارد؛ `ThermodynamicCycleAnalyzer` باید در مسیر انتخاب با CoolProp و statusهای provider مقایسه شود. | capacity و power مستقل از map سازنده می‌تواند ظاهراً قطعی نمایش داده شود. |
| اواپراتور | `EvaporatorSelector.js` مدل `DJ-75-3`، surface/tube volume، اتصال DN و قدرت defrost را از ruleهای تقریبی می‌سازد. | نام LU-VE و قیمت/مدل می‌تواند بدون catalogue performance point در گزارش ظاهر شود. |
| P&ID | `AdvancedPIDGenerator.js` برای پورت ناموجود generic preview port می‌سازد، جایگاه‌های ثابت canvas و DNهای `review-required` دارد و componentها را با fallback می‌سازد. | نقشه از نظر topology و line sizing قابل ساخت نیست؛ صرفاً preview معنایی است. |
| BIM elevation | generator مقدارهای canvas را elevation حقیقی نمی‌داند؛ `TopologyIndustrialCanvas.tsx` برای label ارتفاع ثابت نمایشی استفاده می‌کند. | پمپ زیر separator، separator بالاتر از suction compressor و thermosiphon بین receiver/condenser به‌صورت قابل‌آزمون اجرا نشده‌اند. |
| چاپ | `CalculationBook` از layout صفحهٔ برنامه چاپ می‌گیرد و template چاپی مستقل ندارد. | PDF خروجی calculation book حرفه‌ای ایجاد نمی‌شود. |

## معیار پذیرش اصلاح

1. هیچ equipment record نباید manufacturer و model متناقض داشته باشد.
2. هر capacity/power shown باید یا دارای **manufacturer performance map evidence** در همان operating point باشد، یا با status `manufacturer-map-required` نمایش یابد؛ مورد دوم حق final selection ندارد.
3. سیستم باید بارهای component را از ورودی‌های واقعی محاسبه کند و پیش از شروع، assumptions پیشنهادی را برای تأیید user نشان دهد. هر ورودی غایب باید به‌عنوان `input-required` بماند، نه عدد تخمینی پنهان.
4. P&ID باید برای cycle انتخابی یک line-list، direction، service، DN status، tag و review gate داشته باشد و از graph جداگانهٔ نمایشی تولید نشود.
5. BIM باید `elevation`، datum، clearance، NPSH input/status و port contract را به‌عنوان دادهٔ scene داشته باشد؛ renderer تنها مصرف‌کنندهٔ آن باشد.
6. Calculation Book باید یک print-only report با header/footer، revision، design basis، assumptions، load schedule، cycle, equipment-selection evidence و limitation register بسازد.

## مرزهای فعلی

پیاده‌سازی کامل انتخاب نهایی برای ۱۸۰۰ kW در R717 بدون curve/map و revision سازنده مجاز نیست. در این مرحله، اصلاح صحیح این است که نرم‌افزار **design concept و candidate role** ارائه کند، ولی equipment model/capacity/motor را تا دریافت map معتبر، `review-required` یا `manufacturer-map-required` نگه دارد. این محدودیت کاهش قابلیت نیست؛ حذف ادعای نادرست از خروجی است.

## یافته‌های خارجی ثبت‌شده برای قرارداد elevation

راهنمای **Johnson Controls/Frick Thermosyphon Oil Cooling, Form 070.900-E** تصریح می‌کند که منبع مایع thermosiphon باید بالاتر از oil cooler قرار گیرد؛ بیش از ۶ ft (۱٫۸ m) بالاتر از centerline cooler معمولاً عملکرد رضایت‌بخش می‌دهد، اما head لازم باید از design واقعی محاسبه شود. همان راهنما چهار برابر جریان تبخیرشده را به‌عنوان overfeed متعارف توضیح می‌دهد، header supply را با شیب ۱/۴ in/ft در جهت جریان و header return دوفازی را با شیب حداقل ۱/۴ in/ft به سمت vessel پیشنهاد می‌کند. این‌ها ruleهای بصری ثابت نیستند و به pressure-drop، heat rejection و geometry وابسته‌اند. [1]

صفحهٔ محصول **Sabroe PSH Pump Vessel** نقش vessel کم‌فشار در pumped recirculation را جداسازی liquid برگشتی از evaporator، feed پایدار به pump و gas suction خشک بیان می‌کند. این منبع ابعاد، NPSH یا elevation عددی برای پروژهٔ حاضر نمی‌دهد؛ بنابراین نرم‌افزار باید `NPSH/elevation input required` نمایش دهد و اجازهٔ ادعای final placement ندهد. [2]
